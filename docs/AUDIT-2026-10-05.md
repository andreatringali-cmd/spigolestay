## Fase 1 — sicurezza (PRIMA di andare online)
Quasi tutto il backend usa la service role: l'isolamento tra clienti dipende dai controlli nelle route. Le RLS reali non sono nel repo (esportare `pg_policies` e committarle).
- [ ] `/api/email` senza auth = relay aperto (phishing dal dominio); `esc()` non escapa `"`; throttle solo per `notify`. Fix: funzione interna o firma HMAC per i chiamanti server, rate limit persistente
- [ ] `/api/stripe/portal`, `/customer`, `/invoices`, `/mode`, `/session`: senza auth (takeover fatturazione)
- [ ] `/api/stripe/connect`: senza auth, `accountId`/`returnUrl` dal body
- [ ] `/api/channex/ari`, `/map`, `/fix-occupancy`: senza auth o senza controllo di proprietà (azzerare/gonfiare disponibilità di altri hotel; dirottare prenotazioni OTA)
- [ ] `/api/ical`: SSRF aggirabile (redirect, IPv6, DNS), anonimo, senza limite
- [ ] Snapshot pubblico (`public_sites`): contiene `bookings[].id` (unico segreto dei link ospite), `accessInfo` (codici serratura), `stripeAccount`. Fix: whitelist di campi, token ospite firmato con scadenza
- [ ] `/api/checkin` GET/POST e `/api/manage-booking/cancel` con solo l'id prenotazione: PII, documenti, annullamento, rimborso
- [ ] `/api/public-booking`, `/api/stripe/book`, `/quote`, `/quote/confirm`, `/checkin/pay-confirm`: prezzo/acconto/PI/account dal client; pagamento non legato alla prenotazione; nessun controllo disponibilità
- [ ] Webhook WhatsApp e Channex senza firma; Stripe: un solo secret per Connect e piattaforma, risponde 200 sugli errori, non controlla `event.account`
- [ ] `Origin` header usato per costruire URL server-to-server (SSRF/phishing): usare solo `NEXT_PUBLIC_SITE_URL`
- [ ] `/api/org/invite`: auto-join come owner di un'org altrui con structureId noto
- [ ] Segreti HMAC con fallback hardcoded (`CRED_SECRET`): fallire in chiusura
- [ ] Paywall/invito solo lato client; `authTenant` non controlla abbonamento; `profiles` scrivibile? (verificare RLS)
- [ ] `/api/ai/checkin-extract`, `/api/checkin/extract` anonime (costi Anthropic, foto documenti)
- [ ] `npm audit`: 3 vulnerabilità (nanoid, sharp/libheif; 1 critica)
- [ ] Nessun middleware, CSP, rate limiting persistente, Turnstile lato server

## Fase 2 — architettura dati (soluzione definitiva)
- [ ] Prenotazioni, ospiti, camere su TABELLE vere (una riga per entità, tenant_id, RLS), caricamento a finestra; il browser tiene solo una cache (IndexedDB). Spariscono merge a 3 vie e lapidi
- [ ] Cancellazioni di massa: cestino/soft-delete con ripristino per N giorni, soglia con conferma forte anche lato server
- [ ] Push ARI (disponibilità/prezzi) verso Channex lato SERVER dopo ogni scrittura (oggi solo dal browser aperto → overbooking)
- [ ] Modifica OTA: aggiornare la prenotazione esistente (stesso id) invece di splice+ricrea (si perdono paid, note, check-in, fatture); ACK solo dopo scrittura riuscita (`rev === null` oggi ACKa senza scrivere)
- [ ] Assegnazione camera server-side: mai `ofType[0]` se occupata (public-booking, quote/confirm, channex-inbound)
- [ ] Sync: non scaricare il blob da 5 MB ogni 4 s (leggere prima `rev`); timestamp assegnato dal server invece di `Date.now()` del client
- [ ] Chiavi piatte (cassa, users, billing, rateplans, pricerules, promos…) senza merge: vince il locale
- [ ] Marcatore del proprietario del localStorage (mix di account su stesso browser)
- [ ] Lapidi: il tetto `slice(-3000)` scarta per prime le lapidi del server; con tabelle vere il problema sparisce
- [ ] Foto documento/firme in base64 dentro `data:v1` (spostare su Storage)
- [ ] Schema DB reale non versionato (`app_state`, `org_state`, trigger) → esportare in supabase/migrations

## Fase 4 — correttezza e rifinitura
Logica (da riprodurre con test):
- [ ] Camere bloccate (`blocked`) non riducono la disponibilità venduta sul sito/widget/metasearch (prenota/page.tsx:134 e altri 5 punti) mentre calendario e ARI le contano
- [ ] `moveBooking` non aggiorna `roomTypeId` nella stessa struttura → ARI sbagliato; tipologie derivate con `totalUnits` 0
- [ ] Prezzi OTA/sito ignorano `rateForDay` (derivate, override giornalieri)
- [ ] Rimborso Stripe nel contesto sbagliato (destination charge ma `refunds.create` con `stripeAccount`); prenotazione annullata anche se il rimborso fallisce; manca `reverse_transfer`
- [ ] Acconto: con piano senza anticipo l'ospite paga tutto ma `paid: 0`; senza Stripe `paid: deposit` fittizio
- [ ] Cassa: commissioni stimate di prenotazioni future come uscite; importi arrotondati all'euro (`Math.round(parseFloat)`) in cassa/page.tsx:168,210
- [ ] Alloggiati: schedine già inviate rimesse "pronte" e reinviate; cittadinanza ISO2 scambiata per sigla provincia (FR→Frosinone…)
- [ ] iCal OTA: `DTEND+1` applicato ai feed standard (notte fantasma); prenotazioni sparite dal feed mai annullate; sync ogni 15 min sovrascrive modifiche manuali
- [ ] Tassa di soggiorno calcolata in 3 modi diversi (booking.ts, citytax.ts, invoicing)
- [ ] KPI Prenotazioni includono cancellate/no_show; no_show trattati in modo diverso nei vari punti
- [ ] Fatturazione XML: IVA riga per riga vs per aliquota (scarto SdI), arrotondamento senza riga, bollo ordinario non applicato, invio doppio, `nextAutofatturaNumber` non atomico
- [ ] Date calcolate in UTC (`toISOString().slice(0,10)`) tra 00:00 e 02:00 Rome (BookingDrawer, ConversazioniPanel, documenti, bookedOn, sendReady)
- [ ] `toISO`/`toNum` in ics.ts (fuso, separatore migliaia); codici prenotazione duplicati negli import/gruppi; commissione copiata su ogni camera di un gruppo
- [ ] `addBooking` in cicli usa `bookings` stantio (codici duplicati); import massivo: un `logAct`, un suono, una fetch GCal per riga
UI:
- [ ] BookingDrawer: nessun controllo sovrapposizioni/date (check-out ≤ check-in, adulti 0, incasso negativo)
- [ ] Impostazioni → ripristino backup senza conferma né controllo account
- [ ] Banner "in regola con gli adempimenti" verde anche se le query falliscono
- [ ] Eliminazioni senza conferma (eventi calendario, manutenzione, segnalazioni, recensioni, "Svuota newsletter" senza timeout)
- [ ] Modelli DEFAULT che ricompaiono dopo l'eliminazione; scorte/promo di esempio create al primo accesso
- [ ] `CalendarGrid.syncNow` scrive "ultimo aggiornamento" anche se l'import fallisce
- [ ] Traduzioni mancanti (CalendarGrid, adempimenti, nuova prenotazione, recensioni…), pulsanti solo icona senza aria-label, dashboard-2 duplicata
Prestazioni (da ~500 prenotazioni): indici `guestsById`/`bookingsByUnit` nel provider; Ospiti O(n×m) a ogni tasto; Prenotazioni/Calendario senza memo né paginazione; ChannexAutoSync O(giorni×tipologie×prenotazioni); query Supabase senza paginazione (cap 1000); cron/webhook che scansionano tutti i tenant; timer e listener `focus` non coordinati.
